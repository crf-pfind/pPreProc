==================
数据保真度与边界
==================

峰数组
======

PFB 将导出的每个 m/z 和强度值保存为小端 IEEE 754 binary64。该格式不会对
这些数值进行十进制舍入、量化或有损重压缩。

元数据
======

PFC 保留已验证预处理和带索引访问流程所需的元数据。命名字段覆盖谱图标识与
关联、保留时间、仪器上下文、活化与前体属性、峰数量和 PFB 字节边界。

这是明确的接口边界，并不表示 PFC 会序列化所有厂商 API 中的全部属性。

==============================  ========================================
数据                            v1 保证
==============================  ========================================
导出的 m/z 和强度               以 binary64 保存，不产生格式层面的损失
PFC 核心命名字段                按 v1 规范保留
新增可选 PFC 列                 兼容读取器可接受
全部厂商原生元数据              不保证
厂商原生标识符字符串            v1 没有专门字段保证
离子淌度坐标                    v1 核心字段不保证
==============================  ========================================

当流程需要声明范围以外的属性时，应保留并查询原始厂商数据。读取器不应根据
谱图顺序或其他字段推断未表示的值。
