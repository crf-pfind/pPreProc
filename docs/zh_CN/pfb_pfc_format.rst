=====================
PFB/PFC v1 文件格式
=====================

基本约定
========

PFB/PFC v1 是一种成对出现、支持索引访问的数据表示：

* ``name.pfb`` 保存谱图属性、m/z 数组、强度数组和尾部索引；
* ``name.pfc`` 保存对应的制表符分隔元数据。

PFB 记录序号、尾部索引项序号和 PFC 数据行序号必须指向同一张谱图。
公共 API 中序号从 0 开始。``ScanNo`` 是元数据标识符，不要求等于序号。

基本类型
========

所有数值字段均使用小端字节序。

=================  ================================  ========
名称               编码                              大小
=================  ================================  ========
``int32``          有符号二进制补码整数              4 字节
``uint32``         无符号整数                        4 字节
``uint64``         无符号整数                        8 字节
``binary64``       IEEE 754 双精度浮点数             8 字节
=================  ================================  ========

m/z 和强度数组均使用 ``binary64``。PFB 格式本身不执行十进制舍入、量化或
有损重压缩。

PFB 布局
========

文件头
------

固定文件头占 24 字节。

======  ==========  ==================  ============================
偏移    类型        字段                v1 含义
======  ==========  ==================  ============================
0       ``int32``   ``reserved_1``      保留字段
4       ``int32``   ``reserved_2``      保留字段
8       ``int32``   ``reserved_3``      保留字段
12      ``uint64``  ``index_address``   尾部索引的绝对字节偏移
20      ``int32``   ``spectrum_count``  记录数及 PFC 数据行数
======  ==========  ==================  ============================

谱图记录
--------

每条记录依次包含：

#. ``uint32 property_byte_count``；
#. 指定长度的 UTF-8 属性文本；
#. ``uint32 peak_count``；
#. ``peak_count`` 个 ``binary64`` m/z 值；
#. ``peak_count`` 个 ``binary64`` 强度值。

记录之间不定义额外的对齐填充。

尾部索引
--------

从 ``index_address`` 开始恰好保存 ``spectrum_count`` 个 ``uint64`` 偏移。
第 *i* 项直接指向第 *i* 条记录。偏移必须严格递增，第一项必须为 24，
最后一条记录必须恰好结束于 ``index_address``。因此读取器无需解析前面的
记录即可直接访问目标谱图。

PFC 元数据
===========

PFC 是 UTF-8 编码的制表符分隔文本，包含一行表头以及每张谱图对应的一行
数据。读取器按字段名取值，并允许存在附加列。v1 核心字段包括：

* 标识和关联：``ScanNo``、``PrecursorScan``；
* 采集信息：``RetTime``、``SpectrumType``、``InstrumentType``、
  ``IonInjectionTime``；
* 碰撞与前体信息：``activationType``、``activationCenter``、``NCE``、
  ``monoIsotopicMz``、``upperCharge``、``lowerCharge``、
  ``activationWindow``；
* 跨文件一致性：``NumberofPeaks``、``StartPos``、``EndPos``。

``ScanNo`` 不能为空且必须唯一。三个一致性字段必须与对应的 PFB 记录和
尾部索引相符。

数据保真边界
============

PFB 使用双精度保存写入器提供的 m/z 和强度数值。PFC 有意保留已验证的
预处理和快速访问工作流所需的元数据，但不是所有厂商专有属性的完整序列化。
如果工作流依赖未列出的原生标识符、离子淌度坐标或其他厂商字段，应同时
保留并查询原始数据。

兼容性与验证
============

合规读取器应拒绝无效的文件头或索引范围、不一致的记录长度、缺失的核心
PFC 字段、重复扫描标识、行数不一致，以及谱峰数或字节边界不一致。对于
没有有效 v1 尾部索引的旧版 PFB，读取器不会静默猜测其格式。

具有规范效力的完整英文文本见仓库中的
`PFB/PFC v1 规范 <https://github.com/crf-pfind/pPreProc/blob/main/docs/PFB_PFC_SPECIFICATION_V1.md>`_。
